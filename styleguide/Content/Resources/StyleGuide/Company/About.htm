About this style guide

This Flare project is the style guide the House Style plugin checks topics against. It has two folders under Content/Resources/StyleGuide:

Google: the Google developer documentation style guide, compiled into rules. The plugin updates this folder when Google changes the guide. Don't edit it: change Google rules from the Company folder instead.

Company: your rules. Where they disagree with Google, the company rules win, and the open documentation project's own variables and glossary win over both. This is Google's own order: project-specific style first, then the Google guide.

How to write rules

Only bullets and table rows are rules; paragraphs like this one are context. Keep one rule per bullet. Under a bullet, add a nested list with Bad: and Good: lines so the AI's use of the rule can be tested.

Tables with the headers Avoid, Use, Severity, Why, Example become automatic rules with one-click fixes. In Use, write (delete) to delete the text, or leave it empty to only flag it. Several Avoid entries can share one row, separated by commas; give Use the same number of entries to pair them. A table with Pattern instead of Avoid takes a regular expression, for formats words can't express.

A table with the headers Rule, Setting, Reason turns rules off or changes their level (off, error, warning, suggestion). You don't need to write these rows: in the review pane, select a suggestion and then Turn off rule…, and the plugin writes the row. Writers who can't change the guide see Request a change… instead, and the owners decide.

Every rule has a permanent id, kept on its bullet or table row. You don't see or manage it: Validate style guide gives new rules their ids, so feedback about a rule stays with that rule when you add, move or copy rules.

A table with the single header Role names lists the words your team uses for its readers, such as administrators or editors. Rules that name a role instead of "the user" show these names in their findings, and the AI suggests them. Put the table in any topic of your guide.

Where a rule applies

Rules apply everywhere unless you tag them. To limit a rule to sections with a kind of content, apply a Content condition tag to the bullet, the table row, or the heading above a group of rules: Code, Steps, Lists, Numbers, Tables, Links, Headings, Images, UI, Notes, Examples, Math, API, Footnotes, Emphasis. A table row tagged Headings is checked in headings only.

To limit a rule to some of your products, apply a Product condition tag. The Product tag set lists the products this guide covers: add your products there. Rules tagged for a product that isn't in the list never load, including Google's Android, GoogleCloud and GoogleWorkspace entries.

After editing, select House Style > Validate style guide: every table row is tested against its Example.
